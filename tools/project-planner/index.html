Project Planner

Plan and track projects: tasks on a board, notes and decisions, and a risks & issues log. Saved in this browser, and to a folder on your PC (for example inside a GitHub repo) or straight to GitHub.

How to use
  1. New project, or Import Markdown to paste a plan (for example one written in a Claude chat). Headings become phases, - [ ] item lines become tasks, and sections called Risks, Issues, Decisions or Notes go to the right place.
  2. Quick-add tasks with shortcuts: Write ILR return query @Luke !high due:2026-12-01 #Build (owner, priority, due date, phase).
  3. Board: drag cards between To do, Doing, Blocked and Done. Click any task, note or risk to edit it.
  4. Write-ups drafts a status update, project brief, closure report or README from the project: red/amber/green status with reasons, and a finish-date forecast based on how fast tasks have actually been getting done. Edit it, then copy, download or save it into the project's docs folder (or GitHub). Copy prompt wraps the project data into a prompt for Claude, ChatGPT, Copilot, Gemini or any other AI chat; tick Short version if a tool says it's too long.
  5. SQL: keep the project's queries together, with a database, tags and a description. Send one to the SQL Checker or Query ERD in a click, or use Save to project in the SQL Checker. History keeps earlier versions. Saved to the folder / GitHub as sql/*.sql; if you edit or add .sql files there (SSMS, VS Code, git pull), Reload from folder brings the changes in.
  6. Diagrams: attach process maps from the Flowchart Builder (or use Add to project… there). They stay linked, so edits in the builder show up here; they're saved with the project as diagrams/*.svg and .flow.json, shown in the README, and included in AI prompts as Mermaid text.
  7. Copy as Markdown gives you the whole project as text to paste back into a chat, email or README.
  8. Save to a folder (Chrome or Edge): pick a folder once, e.g. a projects folder inside a GitHub repo on your PC. Every change is written there as project.json plus a readable README.md, one subfolder per project. Commit and push with GitHub Desktop or git.
  9. Open from GitHub lists every project saved in your repo, including ones that are no longer in this browser (new PC, cleared history), and opens any of them. Each saved project gets a View on GitHub link in its header.
  10. GitHub (optional): save straight to a repo using a personal access token. This is the only part of the toolkit that talks to the internet, and only when you click it. Use a fine-grained token limited to one repo with Contents: read and write.
  11. Everything also saves in this browser automatically. Use Export file for a backup or to move to another PC.
  12. Screens: upload Screen Designer exports (.uafx). You can read each page version's DataLinks (SQL) and layout, see checks (validator problems, hard-coded dates, expander columns, writeback tables, access groups), send a DataLink to the SQL store or the EBS Validator Fixer, and download the original file again.
