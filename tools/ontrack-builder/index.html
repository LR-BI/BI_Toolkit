Ontrack Page Builder

Pick what a Screen Designer page should do: defaults, show/hide, required fields, locks, format checks, grid colours, banners, buttons and after-save steps. It writes one <script> for a CustomHTML control, plus a test plan. No jQuery needed, and it re-runs itself after every ajax refresh.

How to use
  1. On the live screen press F12, open Console, and paste the Field lister (tab on the right). It prints every field with its DataLink and copies the names. Paste them into Fields on this screen.
  2. Set the DataLink most fields use. For a field from another DataLink, write DataLink.FIELD (e.g. PersonDetails.DATE_OF_BIRTH).
  3. Add rules. Each can have conditions (when MODE is FT and DATE_OF_BIRTH age at 31 Aug is 16-18). Ages use 31 August of the current academic year, as the ILR does.
  4. Formulas use {FIELD} for a field's value, plus age(), today(), date(), num(): e.g. num({HOURS_PER_WEEK}) * 36.
  5. Copy the Script into one CustomHTML control on the page (anywhere; banners and buttons placed "at the script" appear where that control is).
  6. Work through the Test plan on the test system, with Debug ticked so F12 shows what each rule did. Untick it for live.

Required fields and format checks stop the Save button (any button whose text has the "Save words") and show what's wrong. That's a convenience, not security: back it up with a table constraint or workflow check if it really matters.
