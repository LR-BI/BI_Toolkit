SQL Checker

Paste a T-SQL query to catch common logic bugs, performance traps and things the EBS Central query validator rejects. Checks run in your browser as you type.

How to use
  1. Paste a query into the box. Checks run as you type.
  2. Results are errors (almost always wrong), warnings (often wrong, check them) and tips (performance or style). Untick Show tips to hide tips.
  3. Click a result to highlight that spot in your query. Most results show a suggested fix underneath.
  4. For EBS Central screens, keep EBS mode on. When the validator rejects something new, add it to the list and it will be flagged from then on.
  5. It's a pattern checker, not a full SQL parser, so treat each hit as a question to check rather than a certain bug.

What it checks
error= NULL or <> NULL in a condition. Never true. Use IS NULL.
errorEBS mode: anything on your rejects list, e.g. OUTER APPLY, STRING_AGG, with a rewrite that the validator accepts.
warnAND and OR at the same level with no brackets.
warnEXISTS subquery that never refers to the outer query.
warnNOT IN (SELECT ...). One NULL makes it return nothing.
warnA LEFT JOIN table filtered in WHERE. This makes it an inner join.
warnInteger division with COUNT, e.g. percentages that come out as 0.
warnTOP with no ORDER BY. Which rows you get is random.
warnDates like '01/08/2026'. Day/month order depends on login language.
tip'2026-08-01' with datetime under British settings, BETWEEN with date-only ends, functions on columns in WHERE/ON, leading % in LIKE, SELECT *, DISTINCT, UNION without ALL, NOLOCK, comma joins.

This is a pattern checker, not a full SQL parser. It can miss things and can flag something you meant to do. Treat each hit as a question to check.
