SQL Checker

Paste a T-SQL query and it runs through seven steps: structure, names, query shape, logic, performance, your schema and the EBS validator. It catches syntax slips SQL Server would reject, as well as logic bugs that run but give wrong answers. Checks run in your browser as you type.

How to use
  1. Paste a query into the box. Checks run as you type.
  2. Save to project… keeps the query in a project in the Project Planner (its SQL tab). If you opened the query from a project, Save back updates it there.
  3. The row of numbered steps shows what was checked: ✓ means that step passed, a number means it found something (click it to jump there).
  4. Results are errors (SQL Server will reject it, or it's almost always wrong), warnings (often wrong, check them) and tips (performance or style). Untick Show tips to hide tips.
  5. Load your database in the Schema Map tool to switch on step 6: it then checks that every table and column exists, suggests the right name for typos, and spots text compared with number columns.
  6. Click a result to highlight that spot in your query. Most results show a suggested fix underneath.
  7. For EBS Central screens, keep EBS mode on. When the validator rejects something new, add it to the list and it will be flagged from then on.
  8. It checks without connecting to a database, so treat each hit as a question to check rather than a certain bug.

What it checks
1 StructureUnclosed quotes, comments, [ and brackets; extra or missing commas; BEGIN/END, CASE/END, TRY/CATCH pairs; GROUP/ORDER without BY; empty IN (); a condition missing after AND, WHERE or =; common keyword typos; WITH needing a ; before it.
2 NamesAliases that don't exist, a table name used after it's been aliased, the same alias twice, undeclared or unused variables (SSRS parameters are recognised), unused CTEs, SELECT aliases used in WHERE/GROUP BY.
3 Query shapeColumns missing from GROUP BY, aggregates mixed with plain columns, aggregates or ROW_NUMBER() in WHERE/ON, nested aggregates, JOIN without ON, ON after APPLY/CROSS JOIN, UNION column counts, ORDER BY in subqueries, views or before UNION, unnamed or duplicate columns in CTEs/derived tables/SELECT INTO, INSERT column/value counts, CTE column lists, multi-column subqueries.
4 LogicEverything below, plus ON conditions that don't mention the joined table, a column compared with itself, x = 1 AND x = 2, NOT IN (..., NULL), DATEDIFF(YEAR) used as an age, UPDATE/DELETE without WHERE, temp tables created twice, subqueries that could return several rows, LIKE with no wildcard.
6 SchemaWith Schema Map loaded: unknown tables, unknown columns (with a "did you mean"), text compared with number columns and numbers compared with text columns.
error= NULL or <> NULL in a condition. Never true. Use IS NULL.
errorEBS mode: anything on your rejects list, e.g. OUTER APPLY, STRING_AGG, with a rewrite that the validator accepts.
warnAND and OR at the same level with no brackets.
warnEXISTS subquery that never refers to the outer query.
warnNOT IN (SELECT ...). One NULL makes it return nothing.
warnA LEFT JOIN table filtered in WHERE. This makes it an inner join.
warnInteger division with COUNT, e.g. percentages that come out as 0.
warnTOP with no ORDER BY. Which rows you get is random.
warnDates like '01/08/2026'. Day/month order depends on login language.
tip'2026-08-01' with datetime under British settings, BETWEEN with date-only ends, functions on columns in WHERE/ON, leading % in LIKE, SELECT *, DISTINCT, UNION without ALL, NOLOCK, comma joins.

It reads the query the way SQL Server would but without a database connection, so it can't know every table or column unless Schema Map is loaded. It can miss things and can flag something you meant to do. Treat each hit as a question to check.
